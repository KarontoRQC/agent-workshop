# Codebase Navigator

为**任意语言 / 框架**的项目生成和维护 `AGENTS.md` + 镜像 `docs/ai-nav/` 目录。

---

## 语言规则(最高优先级)

**所有生成的文档内容必须使用中文编写。** 包括:
- `AGENTS.md` 中的所有标题、描述、规则说明
- `docs/ai-nav/` 中所有 `.nav.md` 和 `_index.nav.md` 的标题、描述、表格内容
- 禁止事项的描述文字

**保持原文的内容:**
- 代码标识符(类名、方法名、变量名)
- 文件路径和目录名
- 包名和技术术语缩写(如 URP、RTS、A*、ORM、DI)
- 代码块内容

---

## 第 0 步:探测项目栈(关键)

在任何模式下,**首先探测项目使用的语言、框架和构建工具**,后续的"主要语言"、"跳过规则"、"命令"都依赖此结果。不要假设任何特定技术栈。

### 探测方法

1. **读取清单 / 构建文件**(存在哪个就读哪个,可同时存在多个):

   | 清单文件 | 推断 |
   |---|---|
   | `package.json` | Node / JS / TS;读 `scripts`、`dependencies` 判断框架(React、Vue、Express、Next 等) |
   | `tsconfig.json` | TypeScript |
   | `go.mod` | Go |
   | `Cargo.toml` | Rust |
   | `pyproject.toml` / `setup.py` / `requirements.txt` | Python |
   | `pom.xml` / `build.gradle` / `build.gradle.kts` | Java / Kotlin / JVM |
   | `*.csproj` / `*.sln` / `*.asmdef` | C# / .NET(含 Unity) |
   | `Gemfile` | Ruby |
   | `composer.json` | PHP |
   | `pubspec.yaml` | Dart / Flutter |
   | `mix.exs` | Elixir |
   | `CMakeLists.txt` / `Makefile` | C / C++(辅以扩展名判断) |

2. **统计源文件扩展名** 作为补充与交叉验证:
   ```bash
   git ls-files 2>/dev/null | sed 's/.*\.//' | sort | uniq -c | sort -rn | head -20
   # 非 git 项目:
   # find . -type f -not -path '*/.*' | sed 's/.*\.//' | sort | uniq -c | sort -rn | head -20
   ```
   占比最高且属于源代码的扩展名即"主要语言"。多语言项目(如前端 + 后端)可识别出 2-3 个主要语言,分别处理各自目录。

3. **确定"主要语言文件集"** —— 后续增量模式中"源文件"指的就是这一集合的扩展名(例如 Node 项目为 `.ts/.tsx/.js/.jsx`,Go 项目为 `.go`,Python 项目为 `.py`,Unity 项目为 `.cs`)。

4. **确定命令** —— 从清单文件的脚本 / task 定义中提取真实命令(`package.json` 的 `scripts`、`Makefile` 的 target、`Cargo.toml` 等)。**只列实际存在的命令,绝不编造。**

> 探测结果驱动后文所有"主要语言文件"、"跳过规则按生态选取"、"命令"的填充。

## 触发规则(关键)

本 skill 必须在以下场景自动触发:

### 自动触发 1:提交前同步
**时机**:用户要求提交代码(git commit、/commit 等)
**在**创建提交之前,执行**增量模式**:
1. 检测哪些**源文件**(见第 0 步确定的主要语言文件集)被添加/修改/删除(通过 `git diff --cached --name-only`)
2. 仅为变更的文件重新生成 `.nav.md`
3. 为有文件增删的目录更新 `_index.nav.md`
4. 暂存更新的文档:`git add docs/ai-nav/`
5. 然后继续提交

### 自动触发 2:AGENTS.md 修改
**时机**:任何操作会修改 `AGENTS.md`(用户要求更新规则、添加禁止事项、修改架构等)
**动作**:修改 AGENTS.md 后,检查 `docs/ai-nav/_index.nav.md` 是否需要对应更新(如新增模块、目录规范变更)。保持 AGENTS.md 在 280 行以内 —— 如内容过于详细,移至对应的 `_index.nav.md`。

### 自动触发 3:文件结构变更
**时机**:创建新的源文件、文件重命名或文件删除时。
**动作**:创建/更新/删除对应的 `.nav.md` 并更新父级 `_index.nav.md`。

### 手动触发
**时机**:用户明确调用 `/codebase-navigator` 或说"更新文档"、"同步导航文档"、"重新生成 AGENTS.md"
**动作**:根据用户请求执行完整模式或增量模式。

## 执行模式

### 完整模式(首次或明确要求完整重新生成)

1. **探测项目栈** — 执行上文「第 0 步」,确定主要语言、框架、命令。
2. **映射源码树** — 列出目录和文件,跳过"跳过规则"中的项目。
3. **读取关键文件** — 浏览入口点、核心模块以理解架构。
4. **发现禁止事项** — 从一致的代码模式中推断规则。
5. **创建 `docs/ai-nav/` 目录** — `mkdir -p docs/ai-nav/{mirror paths}`。
6. **生成 `AGENTS.md`** — 280 行以内。结构化路由器,包含模块路由表。**必须使用中文。**
7. **生成导航文档** — 每个文件的 `.nav.md` + 每个目录的 `_index.nav.md`。**必须使用中文。**
8. **报告** — 文件数量,提醒审查,询问 .gitignore。

### 增量模式(提交时或文件变更后)

1. **检测变更**:
   - **git 项目**:`git diff --cached --name-only`(提交前)或 `git diff --name-only`(工作区变更)。
   - **无 git 项目 / 用户要求全量**:回退到全量扫描(等同完整模式的源码树映射),或按用户手动指定的目录 / 文件范围处理。
2. **过滤源文件** — 仅处理主要语言文件(见第 0 步),跳过生成/配置文件。
3. **对每个变更的文件**:
   - 如果**新增**:读取文件,创建 `.nav.md`,更新父级 `_index.nav.md`。
   - 如果**修改**:重新读取文件,重新生成 `.nav.md`(尽可能保留手写的"修改指南"部分)。
   - 如果**删除**:删除其 `.nav.md`,更新父级 `_index.nav.md`。
4. **暂存文档变更** — `git add docs/ai-nav/`(仅 git 项目且在提交前)。
5. **简要报告** — "已为 M 个变更文件更新了 N 个导航文档。"

## 6 大核心原则

### 1. 路由器不是百科

AGENTS.md 是**指针**,不是知识库。它告诉 Codex **去哪里看**,而不是把所有内容都写出来。

- 错误示范:在 AGENTS.md 中粘贴 50 行 API schema 文档
- 正确示范:`API schema 定义在 src/schemas/ 中。修改任何接口前先阅读对应的 schema 文件。`

导航文档 (`docs/ai-nav/`) 的存在就是为了让 AGENTS.md 保持精简。AGENTS.md 负责路由,导航文档负责详情。

**AGENTS.md 单一路由表原则**:AGENTS.md 只维护**一张**「代码目录 → `_index.nav.md`」路由表,**不**直接列功能 / 产品文档清单。

- 模块的功能文档(如 `docs/{module}/{module}.md`)由该模块的 `_index.nav.md` 头部 `> **功能文档**: ...` 行声明
- 全局非目录归属的设计文档(API 契约、整体架构、权限规范)放在顶层 `docs/ai-nav/_index.nav.md` 的「全局架构参考文档」段
- 没有对应功能文档的模块,`_index.nav.md` 不强加这一行

阅读路径:`改代码` → `AGENTS.md`(一张路由表)→ `_index.nav.md`(看逐文件导航 + 顺便看到功能文档链接)→ 按需点开功能文档。

### 2. 禁止 > 建议

禁止事项是可执行的。建议在压力下会被忽略。始终优先使用"禁止做 X"而非"尽量做 Y"。

将禁止事项格式化为独立章节,规则清晰可扫描。

### 3. 只索引你的代码

记录**你项目**的代码,而非库的用法。Codex 已经了解主流框架与标准库(无论是 React、Django、Spring、Rails 还是 Unity)。

导航文档中的外部依赖:仅列出包名,不做解释。

### 4. 可验证

如果一条规则无法检查合规性,它就是噪音。每条指令都应有明确的通过/失败条件。

测试:能否写一个 lint 规则或 grep 命令来检查?如果能,就是可验证的。如果不能,重写它。

### 5. 分层

```
~/.Codex/AGENTS.md                    # 全局:个人默认设置
project/AGENTS.md                      # 项目级:团队共享规则(<280行)
project/src/auth/AGENTS.md             # 目录级:模块特定覆盖
project/.Codex/Codex.local.md        # 个人本地:gitignore 排除
docs/ai-nav/                           # 参考映射:按需读取,非会话启动时加载
```

仅当模块的规则与项目级规则冲突或扩展时,才生成目录级 AGENTS.md。

### 6. hooks 兜底

AGENTS.md 中的规则是尽力而为的。对于每次都**必须**执行的事项,推荐使用 hooks。

- 如果项目统一用 logger 而非 `print` / `console.log` / `System.out` → `禁止使用裸打印输出`
- 如果有统一的错误处理工具且无原始抛出 → `禁止抛出原始异常对象`
- 如果所有组件 / 模块都遵循命名模式 → `禁止命名时不加模块前缀`
- 如果有常量 / 配置文件 → `禁止硬编码魔法数字`

查看 CI/CD 配置、linter 配置(`.eslintrc`、`ruff.toml`、`.golangci.yml`、`.editorconfig` 等)和现有代码审查注释以获取更多线索。

## 跳过规则

跳过规则**按第 0 步探测到的生态选取**,不要对所有项目套用同一份清单。

**始终跳过(与语言无关):**
- 版本控制与 IDE:`.git/`、`.svn/`、`.idea/`、`.vscode/`
- 锁文件、二进制文件、图片、字体、编译输出、source maps
- 不言自明的配置文件
- `.gitignore` 中列出的任何内容(优先以此为准)

**按生态跳过(命中哪个栈就启用对应项):**
- Node / JS:`node_modules/`、`dist/`、`build/`、`.next/`、`coverage/`
- Python:`__pycache__/`、`.venv/`、`venv/`、`*.pyc`、`.pytest_cache/`、`.mypy_cache/`
- Rust:`target/`
- Go:`bin/`、`vendor/`
- JVM(Java/Kotlin):`target/`、`build/`、`.gradle/`、`out/`
- .NET / Unity:`obj/`、`bin/`、`Library/`、`Temp/`、`Logs/`、`TextMesh Pro/`、第三方包目录
- PHP:`vendor/`
- Ruby:`vendor/bundle/`

**始终为以下内容生成导航文档:**
- 第 0 步确定的主要语言的所有源代码
- 包含业务逻辑的配置文件(如构建脚本、schema 定义、序列化资源配置)
- Editor 脚本、代码生成器和项目自有工具

## 更新现有文档

如果 `docs/ai-nav/` 已存在:
1. 仅为变更的文件重新生成导航文档

3. 除非明确要求,否则不重新生成 `AGENTS.md` —— 它可能包含手动编辑的内容
4. 保留现有导航文档中手写的"修改指南"部分
